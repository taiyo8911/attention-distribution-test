# 注意配分検査:運転適正検査 アプリ仕様書

## 1. アプリ概要
- **アプリ名**: Attention Distribution Test（注意配分検査）
- **対象**: 鉄道操縦者の適性検査
- **プラットフォーム**: iOS (iPhone/iPad)
- **画面向き**: 縦向きのみ
- **言語**: 日本語・英語対応（LocalizableStringsで管理）

### 2.2 アーキテクチャパターン
- **MVVM (Model-View-ViewModel)**: 
  - **Views**: SwiftUIで構成された画面表示層
  - **ViewModels**: ビジネスロジック・状態管理（@MainActor）
  - **Models**: データ構造とゲームロジック
  - **Services**: プロトコルベースの依存性注入で、テスト・プレビュー対応

- **責任分離**: 
  - UI変更とビジネスロジックの分離
  - サービス層による永続化処理の抽象化
  
- **再利用性**: 
  - コンポーネント化（GridCell, GridBoard, ConfirmButton等）
  - 両向き対応（PortraitTestLayout/LandscapeTestLayout）

### 2.3 画面状態管理
- **AppScreenState** 列挙型で4つの画面遷移状態を管理：
  - `.start` - スタート画面
  - `.countdown` - カウントダウン画面
  - `.test` - 検査実施中
  - `.finished` - 結果表示画面

## 3. 基本機能仕様

### 3.1 検査内容
- **グリッド構成**: 7×7 = 49マス（デフォルト）
- **配置ルール**:
  - 0は必ず中央位置（3,3）に固定
  - 1～48はランダムに他のマスに配置
- **実施流れ**:
  1. 受験者が「0」から順番に「48」まで数字をタップ
  2. 各タップ後に「確認」ボタンを押して進行
  3. 全数字をタップ完了すると自動的に結果画面へ遷移
- **計測内容**: 開始から完了までの総経過時間（秒単位）

### 3.2 UI要素仕様

#### マス目（GridCell）
- **配置**: 画面いっぱいに7×7グリッド表示
- **形状**: 正方形のセル
- **背景色**: 白（未選択時）、黄色半透明（選択時）
- **境界線**: 黒、1pt
- **数字**: 黒文字、セルサイズの60%フォント、モノスペース体

#### タイマー表示（TestStatusBar内）
- **表示形式**: MM:SS（例：02:45）
- **更新頻度**: 0.1秒間隔の高精度計測
- **動作**: 検査開始と同時にカウント開始、確認ボタンで次へ進む際も継続計測

#### 次に押すべき数字（TestStatusBar内）
- **位置**: 画面上部中央
- **表示**: 大きなフォント（36～50pt）で現在の目標数字のみ表示
- **更新**: 確認ボタン押下時に 0 から 48 に順次更新

#### 確認ボタン（ConfirmButton）
- **位置**: 画面下部中央
- **ラベル**: "確認"
- **状態**: 
  - アクティブ（青色）- マスを選択していて、エラーがなく、検査中の場合
  - グレイ色 - 上記以外
- **動作**: 
  - 正解時 → 次の数字へ進む
  - 不正解時 → エラーメッセージを表示、選択状態リセット
  - 最終数字時 → 結果画面へ遷移

#### 中断ボタン（TestStatusBar内）
- **ラベル**: "やめる"
- **スタイル**: 赤色背景、白文字
- **動作**: 確認ダイアログ表示 → 「はい」でスタート画面に戻る

#### エラーメッセージ（TestStatusBar内）
- **内容**: "正しい数字をタップしてください"
- **色**: 赤色
- **表示条件**: 間違った数字で確認ボタンを押した時に表示
- **消去**: 新しい数字をタップしたら自動消去

#### ワンポイントアドバイス（ResultView内）
- **表示**: 結果画面で「Tip」カードとして表示
- **内容**: TestAdviceから17種類のアドバイスをランダム選択
  - スキャン方法
  - 集中力維持のコツ
  - 練習法
  - 心理的リラックス法など

#### 自己ベスト更新バッジ
- **表示**: 今回の成績が個人最高記録だった場合に結果画面に表示
- **スタイル**: 黄色背景、オレンジ文字で「New Personal Best!」と星マークで装飾

## 4. 操作フロー

### 4.1 基本操作
1. **スタート画面**: 「Start Test」ボタンをタップ
2. **確認ダイアログ**: 「検査を開始しますか?」という確認アラート表示
3. **カウントダウン**: 「開始」選択 → 画面中央に「3 → 2 → 1」と1秒ごとに表示
4. **検査開始**: カウント終了と同時に:
   - 検査画面に自動遷移
   - タイマーが 00:00 からカウント開始
   - グリッド数字配置完了
   - 目標数字「0」が表示される
5. **数字探索**: 受験者が目標数字をタップ → セルが黄色に変化、確認ボタンが青色に変化
6. **確認**: 確認ボタンをタップ
   - 正解の場合 → 目標数字が次の数字に更新
   - 不正解の場合 → エラーメッセージ表示、選択状態リセット
7. **繰り返し**: 「1」～「48」まで手順5～6を繰り返す
8. **完了**: 「48」の確認ボタンタップ → 結果画面へ自動遷移

### 4.2 エラーハンドリング
- **正しいタップ**: セルが黄色に変化、確認ボタンが活性化（青色）
- **間違いタップ**: セルが黄色に変化、確認ボタンは活性化するが確認時にエラー
- **間違いの確認**: 確認ボタンタップ時にエラーメッセージが赤で表示、選択状態がリセット

### 4.3 履歴表示
- **スタート画面**: 「History」ボタンをタップ
- **履歴画面**: 過去の成績を日時と完了時間で表示（新しい順）
- **戻る**: ナビゲーションバーの「戻る」でスタート画面に復帰

## 6. データ仕様

### 6.1 Models定義

#### TestModel
- **用途**: 検査のゲームロジック・状態管理
- **主要プロパティ**:
  - `gameState`: GameState - 検査の状態（未開始・実施中・完了・中断）
  - `gridSize`: Int - グリッドサイズ（デフォルト7）
  - `targetNumber`: Int - 最後に押すべき数字（デフォルト48）
  - `currentNumber`: Int - 今押すべき数字（0～targetNumber）
  - `grid`: [[Int]] - 7×7の数字配置
  - `selectedPosition`: (row: Int, col: Int)? - 選択されているセル位置
  - `showError`: Bool - エラー表示フラグ
- **主要メソッド**:
  - `startTest()` - 検査開始、グリッド生成
  - `resetTest()` - 全て初期化
  - `tapNumber(at:col:)` - マスタップ時の選択状態管理
  - `confirmSelection()` - 確認ボタン時の正解判定

#### TestResult
- **用途**: 検査実績データ（永続化対象）
- **プロパティ**:
  - `id`: UUID - 検査結果の一意ID
  - `startTime`: Date - 検査開始日時
  - `endTime`: Date - 検査終了日時
  - `completionTime`: TimeInterval - 完了時間（秒）
- **備考**: Codable対応、UserDefaultsにJSON形式で保存

#### GameState
- **用途**: ゲーム状態の列挙型
- **ケース**:
  - `.notStarted` - 未開始
  - `.inProgress` - 検査実施中
  - `.completed` - 完了
  - `.cancelled` - 中断

#### AppScreenState
- **用途**: アプリの画面遷移状態
- **ケース**:
  - `.start` - スタート画面
  - `.countdown` - カウントダウン画面
  - `.test` - 検査画面
  - `.finished` - 結果画面

#### TestAdvice
- **用途**: 検査パフォーマンス向上のワンポイントアドバイス集
- **特徴**:
  - 17種類のアドバイスを複数言語対応（Localizable.xcstringsで管理）
  - `TestAdvice.random()` で1つランダム選択
  - 結果画面で毎回異なるアドバイスを表示
- **カテゴリ**:
  - スキャン方法（全体を見る、パターン走査）
  - 集中力・緊張管理
  - 練習法・習慣化
  - 心理的アプローチ

### 6.2 データ保存

#### 永続化方式
- **方法**: UserDefaults（DataServiceで管理）
- **保存先**: ローカルストレージ（アプリサンドボックス内）
- **容量制限**: 最大100件まで（古い順に削除）
- **フォーマット**: JSON（ISO8601日付形式）

#### DataServiceProtocol
- **メソッド**:
  - `saveTestResult(_ result: TestResult)` - 非同期で結果保存
  - `loadTestResults()` - 非同期で履歴取得
  - `deleteTestResult(_ id: UUID)` - 特定結果削除

### 6.3 タイマー管理

#### TimerServiceProtocol
- **精度**: 0.1秒間隔の高精度計測
- **実装**: Combine PublisherでリアルタイムStreamを提供
- **メソッド**:
  - `start()` - タイマー開始
  - `stop()` - 一時停止
  - `reset()` - 0秒にリセット
  - `refresh()` - 経過時間を即座に再同期
- **プロパティ**:
  - `elapsedTimeStream` - AsyncSequence<TimeInterval>で継続更新監視

## 7. 技術仕様

### 7.1 開発環境
- **言語**: Swift 5.9+
- **フレームワーク**: SwiftUI
- **最小iOS**: iOS 15.0
- **対応デバイス**: iPhone、iPad
- **アーキテクチャパターン**: MVVM
- **非同期処理**: async/await
- **状態管理**: @State, @StateObject, @EnvironmentObject

### 7.2 画面サイズ対応

#### レスポンシブデザイン
- **GeometryReader**: 動的にセルサイズ・フォントサイズを計算
- **フォントスケーリング**: dynamicTypeSize制限で読みやすさ確保
- **グリッド計算**:
  - セルサイズ = (利用可能領域 - 境界線幅) / 7
  - 最小セルサイズ: 35pt（小画面対応）
  - フォント: セルサイズの60%

#### 向き対応
- **PortraitTestLayout**: 縦向き用レイアウト
  - グリッドを画面下方に配置
  - ステータスバーはスクロール可能範囲の上に固定
  - セル最小サイズ35pt保証で小画面対応
  
- **LandscapeTestLayout**: 横向き用レイアウト（予定）
  - グリッドと操作パネルを横並びに配置
  - 限られた高さに対応

#### 小画面対応
- **判定**: iPhone SE相当（414×896未満）
- **調整内容**:
  - フォントサイズ削減（36pt）
  - ボタン高さ削減（32pt）
  - 余白削減（6pt）

### 7.3 パフォーマンス要件
- **応答性**: タップ反応は即座に処理（@MainActorで安全性確保）
- **精度**: 0.1秒間隔での時間計測
- **メモリ**: TimerTaskの適切なクリーンアップでリーク防止
- **バッテリー**: 効率的な描画更新（SwiftUI最適化）

### 7.4 テスト対応
- **MockTimerService**: プレビュー・テスト用タイマー
- **MockDataService**: プレビュー・テスト用データサービス
- **Preview**: 複数の状態別PreviewProviderで視覚検証

## 8. Services仕様

### 8.1 TimerServiceProtocol
- **プロトコルベース設計**: 依存性注入対応
- **実装戦略**:
  - Combine PublisherでStream提供
  - AsyncSequenceで非同期イテレーション対応
  - @MainActorで安全な状態更新
- **高精度計測**:
  - RunLoop.current.add(forMode: .common)で安定動作
  - 0.1秒ごとの定期実行
- **クリーンアップ**: Timerの有効期限内での安全な停止・削除

### 8.2 DataServiceProtocol
- **プロトコルベース設計**: 永続化層の抽象化
- **UserDefaults実装**:
  - JSONEncoding/Decodingで型安全性確保
  - ISO8601DateFormatter使用
  - エラーハンドリング（try/catch）
- **非同期操作**: async/awaitで UI ブロッキング回避
- **容量管理**: 100件以上で古い順に自動削除
- **テスト対応**: MockDataServiceでプレビュー・テスト対応

### 9.3 データ永続化
- **非同期処理**: async/awaitでメインスレッドのブロッキング回避

### 9.4 ローカライズ対応
- **Localizable.xcstrings**: 全テキストを外部化
- **複数言語**: 日本語・英語対応

## 10. セキュリティ・プライバシー
- **データ暗号化**: UserDefaultsでのローカル保存（iCloud同期なし）
- **プライバシー**: 個人を特定できる情報は保存しない
- **データ共有**: 外部送信なし（ローカルのみ）
- **削除機能**: 旧データは自動削除（100件超過時）
